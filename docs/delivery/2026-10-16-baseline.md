# 2026-10-16 — Delivery baseline

**Date:** 2026-10-16  
**Scope:** Delivery service, delivery ops frontend, and the links that reach them.  
**Status:** Implemented unless a row says otherwise.

## Delivery service

Package `@bingchun/delivery-service`. Default port `4100`. Public prefix `/delivery-api`.

Driver routes live in [delivery-service/src/routes/](../../delivery-service/src/routes/). Admin delivery routes are mounted from the core backend build (`@bingchun/backend` `adminDelivery` router) in [delivery-service/src/routes/admin.ts](../../delivery-service/src/routes/admin.ts).

### Driver auth

| Feature | Path |
|---------|------|
| PIN login | `POST /auth/login` |
| Refresh token | `POST /auth/refresh` |
| Logout | `POST /auth/logout` |

### Jobs

| Feature | Path |
|---------|------|
| Open jobs for the rider's branches | `GET /jobs` |
| Active job | `GET /jobs/active` |
| Job history | `GET /jobs/history` |
| One job | `GET /jobs/:id` |
| Road route for a job | `GET /jobs/:id/route` |
| Assign | `POST /jobs/:id/assign` |
| Claim | `POST /jobs/:id/claim` |
| Reject before pickup | `POST /jobs/:id/reject` |
| Confirm pickup (branch geofence) | `POST /jobs/:id/pickup` |
| Start the run and issue the customer delivery code | `POST /jobs/:id/start` |
| Complete after return to the branch | `POST /jobs/:id/complete` |
| Report a vehicle failure | `POST /jobs/vehicle-failure` |

A finished stop moves the job to `RETURNING`. Complete requires the rider's coordinates and the branch radius.

### Orders on a run

| Feature | Path |
|---------|------|
| Order on the job | `GET /orders/:orderId` |
| Update stop status | `PUT /orders/:orderId/status` |
| Mark arrived | `POST /orders/:orderId/arrive` |
| Resend the customer delivery code | `POST /orders/:orderId/otp/resend` |
| Verify the delivery code | `POST /orders/:orderId/otp/verify` |
| Record a failed attempt | `POST /orders/:orderId/attempt` |

### Location, route, and live tracking

| Feature | Path |
|---------|------|
| GPS batch upload | `POST /locations/batch` |
| Optimized route for ready orders | `GET /route` |
| Driver socket | namespace `/delivery` |

Socket handshake uses the driver JWT. The rider sends `driver:location`, `driver:online`, and `driver:offline`. Online opens a shift; offline closes it. Location is stored and published as `driverLocation` to the store room and to each order room on the active job. A newer login emits `session_revoked` and disconnects the previous socket.

Internal tracking for core: `GET /internal/orders/:orderId/tracking`.

### Core sync

| Feature | Where |
|---------|--------|
| Outbox worker pushes delivery intents to core | [delivery-service/src/jobs/outboxWorker.ts](../../delivery-service/src/jobs/outboxWorker.ts) |

### Admin API mounted on the delivery service

These are served under `/delivery-api/admin` when the core backend has been built. The delivery ops console calls them through `resolveAdminRequestUrl`.

| Feature | Path |
|---------|------|
| Pending delivery orders | `GET /delivery/pending-orders` |
| Classify orders into a job | `POST /delivery/classify` |
| Preview a route | `POST /delivery/preview-route` |
| List, read, and create jobs | `GET /delivery-jobs`, `GET /delivery-jobs/:id`, `POST /delivery-jobs` |
| Planned, actual, and live route | `GET /delivery-jobs/:id/route`, `/actual-route`, `/live-route` |
| Re-ring an unclaimed job | `POST /delivery-jobs/:id/re-ring` |
| Drivers: list, create, update, ratings, branch pool | `/drivers`, `/drivers/:id`, `/drivers/:id/ratings`, `/branches/:storeId/driver-pool` |
| Live driver positions | `GET /live-drivers` |
| Delivery dashboard | `GET /delivery-dashboard` |
| Rider and fleet analytics | `GET /driver-analytics`, `GET /driver-analytics/rider/:riderId` |
| Failures and reassignment | `GET /delivery-failures`, `POST /delivery-failures/:attemptId/reassign` |
| Complaints: list, detail, resolve | `GET /driver-complaints`, `GET /driver-complaints/:id`, `PATCH /driver-complaints/:id` |
| Branch requests: list and review | `GET /driver-branch-requests`, `PATCH /driver-branch-requests/:id` |
| Branch delivery access and its log | `GET /stores/delivery-access`, `GET /stores/delivery-access-log`, `PATCH /stores/:id/delivery-access` |
| Monthly delivery-order report | `GET /reports/monthly-delivery-orders` |
| Delivery wallet unlock, summary, preview | `POST /delivery-wallet/unlock`, `GET /delivery-wallet`, `GET /delivery-wallet/payout-preview` |
| Payouts: list, due, create, approve, reject, cancel, proof | `/delivery-wallet/payouts` and `/delivery-wallet/payouts/:id/...` |

## Delivery ops frontend

Package in [delivery-frontend/](../../delivery-frontend/). Dev port `3100`. Auth, stores, and notifications still use core `/api`. Delivery admin calls use `/delivery-api/admin`.

| Screen | Route | What it does |
|--------|-------|----------------|
| Staff login | `/login` | Admin session for the console |
| Dashboard | `/` tab `dashboard` | Delivery KPIs; jumps to drivers, complaints, failures, and requests |
| Jobs | `/` tab `jobs` | Job list, filters, job drawer, planned route, actual route replay |
| Drivers | `/` tab `drivers` | Driver list and driver operations |
| Complaints | `/` tab `complaints` | Driver complaints and resolution |
| Failures | `/` tab `failures` | Failed delivery attempts and reassignment |
| Branch requests | `/` tab `requests` | Review rider requests to add, change, or remove a branch |
| Analytics | `/` tab `analytics` | Rider and branch delivery analytics |
| Live map | `/live` | Live driver markers and active jobs |
| Delivery wallet | `/wallet` | PIN unlock, wallet summary, payout approval, payout history |

`NEXT_PUBLIC_DELIVERY_ADMIN_VIA_CORE=true` sends those admin calls through core `/api` instead of the delivery service.

### Customer view of a live delivery

| Main frontend page | What the customer sees |
|--------------------|------------------------|
| `/order/[id]` | Live order status, including the rider on the map while the order is out for delivery |
| `/track/[id]` | Same tracking flow under the track alias |

The delivery code the rider must enter is sent to the customer when the run starts (SMS, in-app notification, and the `deliveryCode` socket event).

### Core backend

| Link | Behavior |
|------|----------|
| `DELIVERY_SERVICE_ENABLED=false` (default) | Core `/api/delivery/*` in [backend/src/routes/delivery.ts](../../backend/src/routes/delivery.ts) is the live driver API. The delivery service stays in the repo for rollback. |
| `DELIVERY_SERVICE_ENABLED=true` | Those legacy driver routes proxy to this service. |
| `/api/admin/delivery*` | Admin delivery, drivers, failures, complaints, branch requests, and the delivery wallet. The delivery service mounts the same router. |
| Outbox to core internal APIs | Delivery writes job and GPS state; core stays the writer of order status, payments, and wallets. See [ADR 0001](../adr/0001-delivery-service-boundary.md). |
